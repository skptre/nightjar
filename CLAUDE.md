# NIGHTJAR
# MASTER CONTEXT FILE — READ THIS BEFORE TOUCHING ANYTHING

## PROJECT IDENTITY

An open internship feed (public repo, shared data) and a local desktop tracker (private, per-user).
The poller is a public service. The app is a local tool. They share nothing except a JSON file on GitHub.
Full spec is in /spec.md — it is the source of truth.

## THE ARCHITECTURE (read this before every design decision)

# [NJ] LAW: The poller knows NOTHING about any user. No profiles, no preferences, no eligibility,
  no scoring, no tiers, no notifications. It fetches, normalizes, dedupes, and commits raw data.
  Every opinion about what's relevant lives in the app.
# [NJ] LAW: Everything upstream of the user is shared and public. Everything downstream is private
  and local. There is no middle ground and no exceptions.
# [NJ] LAW: The repo is PUBLIC. GitHub Actions minutes are unlimited on public repos, capped at
  2,000/month on private. The poller cannot run on a private repo.
# [NJ] LAW: Zero personal data in the repo. No profiles, no application state, no user preferences,
  no tiers, no contacts, no notes. If it's about a person, it stays on their machine.

## [NJ] POLLER LAWS

# [NJ] LAW: A failed fetch is NEVER an empty result. Distinguish `[]` (fetched fine, no jobs) from
  an exception. On failure, retain the previous postings and mark the source unhealthy.
# [NJ] LAW: Posting IDs are `sha256(f"{source}:{company_slug}:{source_job_id}")[:16]`. NEVER include
  title, URL, or location. Companies edit those in place → phantom new postings → feed churn.
# [NJ] LAW: The pipeline is idempotent. Running twice on identical input produces ZERO diffs in
  feed.json. This is tested, not aspirational.
# [NJ] LAW: A posting must be absent for TWO consecutive runs before `closed_at` is set.
# [NJ] LAW: Suppress new-posting flags on a company's first fetch (`bootstrapped: true`).
# [NJ] LAW: Dedupe conservatively. A duplicate is annoying. A false merge hides a role forever.
# [NJ] LAW: Be a good citizen. Honest User-Agent, 1s per-host delay with jitter, backoff on 429/5xx,
  max 3 retries.

## [NJ] APP LAWS

# [NJ] LAW: Eligibility defaults to `unclear`, NEVER `ineligible`. Hiding a real opportunity is the
  worst possible failure. Every `ineligible` verdict MUST cite a matched sentence from the posting.
# [NJ] LAW: Never delete a posting from local storage. Close, collapse, deprioritize — never remove.
# [NJ] LAW: Notification volume is a correctness property. Cap at 15 per sync. A tool that fires 200
  alerts gets muted and then it's dead.
# [NJ] LAW: The app sends NO data anywhere. It fetches a public JSON file. That's it.

## [NJ] SOURCE ADAPTER GOTCHAS

# [NJ] HARD CONSTRAINT: Workday `limit` CANNOT exceed 20. Higher values silently return empty arrays
  with no error — indistinguishable from end-of-results.
# [NJ] HARD CONSTRAINT: Workday throttles fast paging. Sleep 1–2s between pages. Retry failed pages.
# [NJ] HARD CONSTRAINT: Workday pagination: terminate on `offset + limit >= total` OR empty array.
  Check BOTH.
# [NJ] HARD CONSTRAINT: Greenhouse `content=true` returns HTML-entity-encoded text. Unescape first.
# [NJ] HARD CONSTRAINT: Lever `createdAt` is epoch MILLISECONDS.
# [NJ] SPEC: Simplify listings are at `.github/scripts/listings.json` on the `dev` branch.
  Filter on `active == true` AND `is_visible == true`.

## [NJ] EXPLICIT BANS

- DO NOT implement auto-submit, headless navigation, or automated form submission.
- DO NOT add LinkedIn or Indeed scrapers.
- DO NOT put personal data in the repo. Not "be careful" — DO NOT.
- DO NOT build user accounts, auth, or a hosted frontend.
- DO NOT add eligibility, scoring, or filtering to the poller. That's app-side.

## PRIORITY STACK

poller correctness > registry coverage > app filter accuracy > app UX > extension
Phase 2.5 (registry expansion to 300+) is the highest-value, least glamorous work. Not optional.

## TECH STACK

Poller: Python 3.12, uv, httpx, rapidfuzz, PyYAML
Lint/type: ruff + mypy --strict on poller/
Store: JSON in git (data/feed.json, data/state.json)
App: Vite + React + TypeScript (strict) first, Tauri wrap later
App local store: SQLite (better-sqlite3 via Tauri, or sql.js for browser-only phase)
Extension: Chrome Manifest V3

## COMMANDS

make poll        # single poller run against the real registry
make poll-dry    # run without committing
make test        # full offline suite (fixtures only, NO network)
make test-live   # opt-in, hits real APIs
make lint        # ruff + mypy
make dev         # app dev server

## DATA OWNERSHIP

data/feed.json       # GENERATED by poller. Raw postings. No personal data. Public.
data/state.json      # GENERATED by poller. Run metadata, per-source health.
companies.yaml       # HAND-CURATED. The asset. PRs welcome.

App-local (never in repo):
  profile.json       # User's grad date, work auth, tiers, contacts.
  nightjar.db        # SQLite: cached postings, application state, notes.

## BUILD RULES

1. TDD. Tests before implementation.
2. Every source adapter ships with committed fixtures in the same commit.
3. NO NETWORK in `make test`. Ever.
4. Golden-file test: pipeline against fixtures produces byte-stable feed.json.
5. Commit after every working module, not every file.
6. Never break a passing test.
